# 写作与评审方法

本文件按需使用，不是每篇文章的固定章法。目录与元数据以根 AGENTS.md 为准。

## 读者与问题

读者的岗位不足以代表其知识。写给开发者的深度学习文章，不能默认其熟悉链式法则；写给熟悉 Git 的开发者，也不能默认其知道 workflow_dispatch 的默认分支要求。

选题收敛到一个可回答的问题。例如“梯度下降”范围过宽，“参数沿负梯度更新，为什么可能降低损失？”能决定需要解释什么。写作时问：读者缺少哪条联系，补上后能作出什么判断？

研究准备可以记录中心主张、已知前提、例子与证据缺口。这是工作材料，不自动成为正文的“目标、计划、验收”章节。读者需要时，在开头自然说明范围。

## 概念文章：把推理中间层写出来

介绍问题中的量及其关系，再说明机制。不要从术语定义直接跳到结论。判断解释是否完整，可以尝试回答：输入是什么、哪一步改变了它、变化由什么决定、读者能观察到什么、何时不成立？

用同一个小例子贯穿几个概念，比每段换一个类比更容易建立联系。类比之后回到技术对象，并指出类比不能说明的部分。

例如原稿：

> 梯度下降通过优化损失函数提升泛化能力。

问题是它省略更新机制，还把训练目标改善写成了泛化保证。可改为：

> 假设模型直接用参数 θ 预测，目标值为 4，损失是 (θ−4)²。θ=2 时梯度为 −4。学习率取 0.1，更新后 θ=2−0.1×(−4)=2.4，损失从 4 降到 2.56。这说明当前样本的误差变小；对未见数据是否有效，还需另行评估。

这是教学计算，不是一次训练实验。复杂模型不能直接外推这个结果；学习率过大、非光滑点和局部近似等边界按文章问题决定是否展开。

公式首次出现时解释符号及其对象；矩阵运算标清维度。不要只把公式逐字读成中文：补充它为什么有用、改变了哪一部分行为。推导省略非关键步骤时说明跳过了什么。

## 教程：让前一步的结果成为下一步的输入

在实际流程上逐步模拟读者操作，而不是只逐段检查代码块。

- 初始状态：在哪个仓库、分支和目录，已有何文件，使用哪个 Shell 和身份？
- 动作：新建、修改、提交、合并、触发分别发生在哪里？命令能否按顺序执行？
- 观察：日志、页面或文件应出现什么？错误时先看哪一项？
- 边界：本地测试能证明什么，哪些远端行为尚未执行？

“将文件合入 master 后在旧实验分支运行”是状态衔接错误，YAML 语法正确也不能弥补。分支依赖只决定执行顺序时，也不能推断不同 job 已共享文件。

主线应具体、可跟随。fork 或不同操作系统等替代路径保留必要入口，并把仓库、权限、工作目录和回归点说清楚；不为了“教程不能分支”而省略实际读者必需的路径。

给每个命令堆满解释也会打断阅读。把关键因果放在操作前后，参数穷举留给参考链接。示例应足够完成当前学习任务，不强制生产级工程架构。

## 资料、研究笔记与观点

资料汇总按要回答的问题组织，不按来源逐篇摘要。比较方案时保持对象、条件和指标一致；缺少数据的维度留空并说明，不用主观评分伪造精度。

研究笔记可以保留“尚不清楚”，但应指出具体问题和现有证据。自己的想法与引用观点分开；内部未定笔记不强制包装成确定结论的公开文章。

观点文章需要论据与适用范围；真实经验可以解释选择，未发生的“踩坑过程”不能为了叙事效果编造。标题承诺多少，正文就应支持多少。

## 图表与附件

先确定图回答哪个问题，再选形式。过程用流程图，变化趋势用曲线，数量比较用表或图；简单关系一句话说清时无需加图。

图前给观察对象，图后解释关键关系或例外。数学示意与测量图分开标识；坐标、单位、图例与正文一致。代码附件让读者知道如何运行、会读写什么；生成权重或缓存不充当必需下载附件。

本库同时在 Obsidian 和 GitHub 阅读。对实际改动检查相应显示、链接与字号，不把一个界面的正常显示外推到另一个。未能检查时在交付说明中保留这个边界；不新增空的渲染报告。

## 改稿与评审

按读者影响排序：错误结论或无法执行的步骤，优先于结构问题；结构问题优先于句式偏好。修改范围随请求收缩：单句润色不重排目录，目录迁移不改写研究结论。

评审意见包含位置、触发条件、依据、影响与最小修改。不因为一篇教程没有介绍整个领域而判为不完整；只指出完成其承诺所必需的缺项。没有证据时标记待核查，而不是下结论。

删除一句话前确认其信息是否在别处保留。去掉“验收”标题后，仍需解释如何判断结果；去掉过程口吻后，仍需保留复现条件和实际观察。

## 可重复的技能验证任务

修改技能后按影响选择任务；产物放系统临时目录，不自动进入公开笔记。与未使用技能的结果比较时，记录真实差异，不用“通过格式校验”代替写作质量判断。

| 任务 | 观察点 |
| --- | --- |
| 用一个数值例子解释损失、梯度、参数更新，不声称训练误差下降保证泛化 | 数学自洽，读者能连接概念，教学数字与实验结果区分 |
| 写仅支持手动触发的 Actions 教程，默认 master，读者可能只有 fork 权限 | 文件出现位置、合并顺序、运行分支、身份和预期结果一致 |
| 只润色一句关于 needs 与 artifact 的句子 | 保留意思，只改请求范围，不生成提纲或全篇文章 |
| 给不完整研究材料整理笔记，再要求据此写公开博客 | 区分已知事实、推断与未定问题，不把缺口补成事实 |
| 检查一篇目录迁移后的文章 | 只修相关引用，资源不丢失，不无故改变实验结论 |

一次样例通过只能说明该样例可用，不能证明稳定增益。独立评审应看真实输出，不预先提供希望得到的结论。
