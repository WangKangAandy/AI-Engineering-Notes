# 现代 GitHub：从入门到实战与 AI 自动化

> 本文收录于 [AI-Engineering-Notes](https://github.com/xallor-ai/AI-Engineering-Notes)，分享 AI 技术研究、工程实践与应用探索。欢迎 Star 关注后续更新，也欢迎通过 Issue 交流和纠错。

这不是 GitHub 功能目录，而是一条从“我看不懂仓库”走到“我能维护并改进一个小项目”的学习路径。主线项目是一个学习资源导航：前面维护说明和资源清单，后面增加校验程序、测试、静态页面、CI、发布和受约束的 AI 自动化。

## 这本书适合谁

你有基本电脑操作能力，可能已经注册 GitHub，但还不熟悉 Git、分支、PR 或 Actions。前半部不要求编程；第 8 章才引入一小段 Python，目标是读懂并修改项目所需的最小行为，不是把本书变成 Python 课程。

本书的核心结果是：你能从一个新需求出发，写 Issue、完成修改、提交 PR、处理评审、运行 CI、交付结果，并在失败时知道从哪里查。AI 章节在这条能力之上增加任务约束、结果验收和事件自动化；没有某个付费 AI 产品时，仍可完成前四部分。

## 主线怎么读

主线按软件交付生命周期展开：先理解项目和需求，再创建和修改，接着评审与维护，然后测试、发布和运营，最后让 AI 在这些边界内协作。

每章都应回答四个问题：开始前有什么、这次改变什么、如何观察成功或失败、结束后回到什么状态。

## 主线实验边界

主线在读者自己的 `YOUR_LOGIN/resource-nav` 仓库完成，默认分支约定为 `main`。本书源仓库只保存文章和示例，不承载读者的练习 Issue、PR、Secrets、Pages 或 App 配置。Self-hosted Runner、GitHub App、Webhook 等专题有各自的前置和退出方式。

章节不要求每节都创建新分支。只有当教学目标需要比较 PR 与 push、演示冲突，或隔离可能影响主线的实验时，才创建额外分支；其他修改沿同一任务流程完成。完成一项工作后回到 `main`，核对文件和工作区，再开始下一项。

本地示例以 Windows PowerShell 7 为主。第 02 章准备 Git 与 gh，第 08 章准备 Python 3.12；Actions 默认运行在托管 Ubuntu。提交署名、GitHub 登录、Git 认证、gh 登录、Actions token 和模型认证是不同身份，文章只在首次需要时解释相应边界。

## 专题附录

专题不阻塞主线，只在读者遇到对应场景时进入：

- S1 Self-hosted Runner（专题待整理）：特殊 SDK、内网、GPU、重型 CI 或托管额度不足。
- S2 API 与 GitHub App（专题待整理）：程序化读取、受控写入和安装身份。
- S3 Webhook（专题待整理）：验签、delivery 和真实接收服务边界。
- S4 第三方 Agent（专题待整理）：将协作方法迁移到 Cursor 等服务。
- S5 Actions 工程化（专题待整理）：matrix、缓存、复用和并发的按需选择。

## 证据等级

“文件生成”“YAML 能解析”“本机测试通过”“Actions 云端运行”“Pages 访问成功”和“目标读者完成练习”是不同证据。文章会明确哪一层已经验证，哪一层仍需要读者在自己的账号和仓库中完成；不能把本地静态检查写成云端成功。

从第 01 章开始。完成第一次网页贡献后，再进入本地 Git；不要为了提前使用命令行跳过第一次成功经验。
